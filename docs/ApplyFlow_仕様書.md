# ApplyFlow 仕様書 v1.4

更新日: 2026-07-27

## 1. 目的

ApplyFlowは、応募先ごとに分散する選考状況、候補日時、確定面談、返信期限、承諾期限を一元管理し、日程衝突と対応漏れを防止する。

主な利用者は、複数企業の就職・転職・インターン・業務委託選考を並行管理する個人である。

## 2. 実装済みスコープ

- Google OAuthによるログイン
- 応募先、企業、選考フェーズ、面談、候補日時、期限、活動履歴の管理
- ダッシュボード、応募先一覧・詳細、カレンダー、返信待ち、期限管理
- アプリ内予定の衝突検知
- Google Calendar readonly連携、予定表示、衝突検知
- Google Calendar予定のアプリ内予定への取り込み
- Gmail readonly連携、検索、ページング、本文取得
- Cloudflare Workers AI上の`@cf/openai/gpt-oss-120b`によるメール情報抽出
- 抽出内容の確認・修正後の応募情報登録
- Gmail検索条件に合う新着メールの15分間隔監視
- 一意な既存応募への高信頼な選考情報の自動反映
- Green・doda求人詳細を確認後に登録するChrome拡張機能

## 3. Google Calendar連携

### 3.1 読み取り

- Primary Calendarを対象とする。
- 月初から翌々月初までを標準取得範囲とする。
- 繰り返し予定は単一イベントへ展開する。
- キャンセル済み予定は表示しない。
- `transparency=transparent`の予定は表示するが衝突対象から除外する。
- APIページングを処理し、最大2,500件単位で取得する。

### 3.2 アプリへの取り込み

1. カレンダー上のGoogle予定を選択する。
2. 詳細ダイアログで日時、場所、説明を確認する。
3. 必要に応じて応募先を紐付ける。
4. 「この予定を取り込む」を実行する。
5. サーバーがGoogle APIから予定を再取得し、`ScheduleEvent`へ保存する。

同じ`userId / source / externalCalendarId / externalEventId`の組み合わせはupsertし、重複登録しない。取り込み後はAPI由来の同じ予定を表示対象から除外する。

取り込みはApplyFlow側へのスナップショット保存であり、Google Calendarの作成・更新・削除は行わない。

## 4. Gmail・AI抽出

### 4.1 Gmail検索

- ユーザー入力のGmail検索クエリを使用する。
- 1ページ25件を表示する。
- 件名、送信者、日時、スニペットを表示する。
- 選択されたメールだけ本文を取得する。
- 添付されたtextファイルは本文として扱わない。

### 4.1.1 Gmail定期監視

- 監視はユーザーごとに明示的に有効化し、検索条件とAI送信への同意を保存する。
- 初回有効化時の現在時刻より後に受信したメールだけを対象にする。
- Netlify Scheduled Functionが15分間隔でBackground Functionを起動する。
- 検索カーソルには10分の重複区間を設け、検索結果を永続ジョブ化した後にだけ進める。
- 1回の実行は最大25件を逐次処理する。
- Gmail message IDと内容digestで再実行時の重複登録を防ぐ。
- 無料枠、日次AI上限、一時障害時は未処理jobを保持して次回以降へ繰り越す。

### 4.2 本文前処理

- 複数の`text/plain` MIMEパートを重複排除して統合する。
- plain textがない場合はHTMLをテキスト化する。
- Unicode、改行、空白を正規化する。
- 最新本文と引用・転送履歴を分離する。
- 日程変更・キャンセルは最新本文を優先する。

### 4.3 抽出項目

- 会社名、ポジション
- 選考フェーズ種別、表示名
- 候補日時、確定日時
- 返信期限、承諾期限
- 面談URL、担当者名
- 採用関連メールかどうか
- イベント種別（新規・更新、日程変更、取消、情報のみ）
- 総合confidence
- 項目別confidence
- 項目ごとの根拠テキスト

日時は明示的なUTC offset付きISO 8601として抽出する。相対日付はメール受信日時を優先し、次に処理基準日時を参照する。

### 4.4 確認と登録

- 手動メール取込は従来どおり確認画面を経由する。
- confidenceが75%未満の項目を「要確認」として強調する。
- ユーザーは全項目を修正できる。
- 確認後、企業、応募、選考フェーズ、面談、候補日時、期限をトランザクションで登録する。
- 登録済み抽出結果を再実行しても、同じ応募先を二重作成しない。
- 確認済み値を`reviewedJson`として保存する。

### 4.5 定期監視の安全な自動反映

- 自動反映には総合confidenceと変更対象全フィールドのconfidenceが90%以上必要である。
- 正規化した会社名・ポジションが一意な既存Applicationへ完全一致する場合だけ対象にする。
- 新規Company / Applicationは自動作成しない。
- 取消、複数候補、対象Interviewが一意でない日程変更、手入力データと競合する変更は確認待ちにする。
- 日程変更は同じ選考フェーズの有効Interviewが一件だけの場合に限る。
- 手入力のProposedSlot / Deadlineを自動削除・上書きしない。
- 自動変更はDB transactionで実行し、変更前後、対象、抽出結果、冪等性情報を監査履歴へ残す。
- 無関係メールと情報のみのメールは応募情報を変更せず、処理済みとして記録する。

## 5. カレンダー・衝突検知

表示対象は確定面談、提示中候補日時、期限、取込済み予定、未取込のGoogle予定である。

時間範囲`A.start < B.end AND B.start < A.end`を満たす場合に衝突と判定する。

| 組み合わせ | 重大度 |
|---|---|
| 確定 × 確定 | high |
| 候補 × 確定 | medium |
| 候補 × 候補 | low |

同じ面談の確定InterviewとConfirmed ProposedSlotは同一グループとして重複警告しない。Google予定同士も警告しない。

## 6. UI要件

- PCはサイドバー、スマートフォンは5項目のボトムナビゲーションを使用する。
- 現在画面をナビゲーション上で強調する。
- スマートフォンの応募先・期限一覧はカード表示とする。
- カレンダーイベント選択時は詳細ダイアログを表示する。
- 外部API失敗、未連携、空状態、処理中、入力エラーを画面内に表示する。
- キーボードフォーカスを視覚表示し、ダイアログはEscapeで閉じられる。

## 7. セキュリティ・プライバシー

- すべての業務データを`userId`で分離する。
- Calendar取込時はクライアントから送られた予定本文を信用せず、サーバーで再取得する。
- 応募先紐付け時は所有者を検証する。
- Google連携はCalendar/Gmailともreadonlyスコープとする。
- Gmail本文はDBへ保存しない。
- APIキーとOAuthトークンはクライアントへ公開しない。
- Gmail本文は処理中のメモリからCloudflare Workers AI上の`@cf/openai/gpt-oss-120b`へ送信する。Cloudflareの保存サービス、DB、ログへ保存しない。
- Cloudflare Workers AI Freeの1日10,000 Neuronsを超えた場合は翌日へ繰り越し、有料AI APIやWorkers Paidへフォールバックしない。
- ブラウザ拡張機能は専用Tokenで認証し、サーバーにはSHA-256 digestだけを保存する。
- 拡張機能TokenはContent Scriptへ渡さず、求人本文、Cookie、媒体認証情報を取得しない。
- 企業メッセージは利用者が選択し、個別同意した本文だけをAI抽出時に送信する。生本文はDB、Chrome storage、ログへ保存しない。

## 7.1 ブラウザ拡張機能

- Green・dodaの求人詳細では応募先保存、それ以外の媒体ページでは企業メッセージからの面接日時抽出を提供する。
- ページ表示だけではApplyFlowへ通信せず、保存ボタン押下後に保存済み照合を行う。
- 会社名、ポジション、勤務地、雇用形態、給与・報酬、応募種別、メモを確認・修正してから登録する。
- 登録先は既存`Company` / `Application`とし、`route=JOB_BOARD`、`status=DRAFT`、`priority=MEDIUM`で作成する。
- 媒体求人IDまたは正規化URLとIdempotency-Keyで重複を防ぐ。
- 求人一覧の一括取得、自動巡回、自動応募、媒体Cookie・内部APIの利用は行わない。
- メッセージ抽出は選択範囲または貼付本文だけを対象とし、送信前同意と登録前確認を必須にする。
- 確定日時、候補日時、日時変更、取消を既存ApplicationのSelectionStage / Interview / ProposedSlotへ反映する。
- 日時変更・取消は対象Interviewを必須選択とし、Application全体を終了状態にはしない。
- 同一メッセージの重複防止には生本文でなくSHA-256 digestを使用する。
- メッセージから会社名・ポジションも抽出し、完全一致する既存Applicationへ統合する。
- 法人格位置などの表記ゆれ候補は自動統合せず、既存統合または新規作成を利用者が確認する。
- 一致しない場合は同じ確認画面からCompany / Applicationと面接情報を同時登録する。

## 8. 完了条件

- 同じGoogle予定を複数回取り込んでも1レコードになる。
- 取り込んだ予定は再読込後も表示され、Google予定と二重表示されない。
- 終日予定とタイムゾーン付き予定が正しい日付・時刻で表示される。
- Gmailのplain/HTML/引用付きメールを処理できる。
- 有効化後の検索一致メールが2監視周期以内に永続jobになる。
- 高信頼・一意一致だけが一度自動反映され、新規・曖昧・取消・手入力競合は確認待ちになる。
- Gmail本文がDBとアプリログへ保存されない。
- 低信頼項目と根拠を確認画面で識別できる。
- ユーザーのローカル日時を設定タイムゾーンで保存する。
- テスト、型チェック、Lint、production buildが成功する。
- 拡張機能のTypeScript buildが成功し、開発者モードで読み込める。
- 企業メッセージの確定・候補・変更・取消が確認後にダッシュボードと応募先へ反映される。

## 9. 対象外

- Google Calendarへの予定書き込み
- Google Calendarとの常時双方向同期
- Gmail監視の稼働SLA保証
- 過去メールの一括自動登録
- Gmail監視によるCompany / Applicationの新規自動作成
- AI判断だけによる応募ステータスの確定
- 企業メッセージ画面の自動監視・未選択本文の自動送信・AI結果の自動登録

## 10. 旧版からの変更

- v0.1の「Google Calendar / Gmail / AI抽出は将来実装」という記述を廃止した。
- Google予定は非永続表示だけでなく、明示操作によるアプリ内取り込みに対応した。
- AI抽出は総合confidenceだけでなく項目別confidenceと根拠を扱う。
- v1.2で、本人操作・確認を前提としたGreen・doda Chrome拡張機能を実装済みスコープへ追加した。
- v1.3で、企業メッセージから面接の確定・候補・変更・取消を確認登録する機能を追加した。
- v1.4で、Gmailの15分間隔監視、高信頼な既存応募への限定自動反映、Cloudflare Workers AI上の`@cf/openai/gpt-oss-120b`、Netlify / Neon無料デプロイ構成を追加した。
