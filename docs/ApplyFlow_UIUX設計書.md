# ApplyFlow UI/UX設計書 v1.1

更新日: 2026-07-14

## 1. UXの目的

利用者が3秒以内に「次に対応すべき選考・期限・衝突」を把握し、メールやカレンダーから登録する手間を減らす。

最重要メッセージは「今やるべき選考対応が分かる」である。ブランド名ApplyFlow、青を中心とした配色、簡潔で実務的な口調を維持する。

## 2. 情報の優先順位

1. 今日・今週の確定面談
2. 返信待ち
3. 近づいている期限
4. 日程衝突
5. 進行中の応募
6. 外部メール・カレンダーからの登録

確定、候補、期限、Google予定、取込済み予定は色とラベルの両方で区別する。色だけに意味を依存させない。

## 3. 共通ナビゲーション

### PC

左サイドバーを使用する。

- ダッシュボード
- 応募先
- カレンダー
- 返信待ち
- 期限管理
- メール取込
- 設定

現在地は青背景と青文字で強調し、`aria-current=page`を付ける。

### スマートフォン

画面下部に固定した5項目のボトムナビゲーションを使用する。

- ホーム
- 応募
- 予定
- メール
- 設定

返信待ちと期限はダッシュボードのサマリーから到達できる。下部ナビとコンテンツが重ならないよう本文にsafe areaを確保する。

## 5. ダッシュボード

サマリーカード全体をクリック可能にし、対応する一覧へ遷移する。

- 今週の面談 → カレンダー
- 返信待ち → 返信待ち一覧
- 期限間近 → 期限管理
- 衝突 → カレンダー
- 進行中応募 → 応募先一覧

カード内の数値を最も強く、名称、アイコンの順に見せる。下段には今日・今週、返信待ち、期限、衝突の詳細を配置する。

## 6. 応募先一覧

PCは比較しやすい表、スマートフォンは会社単位のカードを使用する。

カードには次を表示する。

- 会社名、ポジション
- 選考ステータス、応募種別、優先度
- 次の予定
- 最も近い期限

カード全体を詳細画面へのリンクにする。

## 7. カレンダー

### 表示

- PCの初期表示は週表示
- 月、週、日を切替可能
- 確定面談: 青
- 候補日時: 淡い青・破線
- 期限: 黄、承諾期限は赤
- 未取込Google予定: グレー
- 取込済み予定: 紫

上部に色と種別の凡例を表示する。

### イベント詳細

イベントを選択すると画面遷移せず詳細ダイアログを表示する。

表示内容:

- 種別、タイトル
- 日時
- 関連応募先
- 場所、説明
- Google側URL、面談URL

内部予定は応募詳細へ遷移できる。ダイアログは閉じるボタン、背景選択、Escapeで閉じられる。

### Google予定取込

未取込Google予定だけに取込フォームを表示する。応募先紐付けは任意とし、「紐付けない」を初期値にする。

処理中はボタンを無効化し、成功・失敗をダイアログ内に表示する。取り込み成功後はカレンダーを再読込し、取込済みの紫色表示へ切り替える。

## 8. Gmail取り込み

検索、結果確認、AI抽出の順に一方向の導線を作る。

検索結果には件名、送信者、日時、スニペットを表示し、メールごとに「抽出」を配置する。処理中は対象メールを「抽出中」と表示する。

未連携・権限不足・期限切れは、原因説明と再ログインボタンを同じカードに表示する。

## 9. AI抽出確認

画面上部に総合confidenceを表示する。75%以上は成功色、未満は警告色とする。

各抽出フィールドは項目別confidenceを参照し、75%未満の場合だけ次を表示する。

- 「要確認 xx%」バッジ
- AIが判断に使った短い根拠

高信頼項目まで警告で埋め尽くさず、利用者が修正すべき箇所に視線を集中させる。

登録前に会社、ポジション、選考、確定日時、候補日時、期限、URL、担当者を編集できる。候補日時は追加・削除できる。

## 10. 期限管理

PCは表、スマートフォンはカードを使用する。スマートフォンではタイトル、応募先、状態、日時、残り時間、完了操作を一画面幅に収める。

## 11. 状態表示

| 状態 | 表示方針 |
|---|---|
| 読込中 | 対象ボタンを無効化し動詞を進行形にする |
| 空状態 | 状態説明と、必要な場合は次の行動を表示 |
| 入力エラー | 対象フィールド直下に表示 |
| 外部APIエラー | 原因と再認証・設定・再試行導線を表示 |
| 成功 | 操作箇所の近くに短い結果を表示 |
| 破壊的操作 | destructive色と確認操作を使用 |

## 12. レスポンシブ

- 主要ブレークポイントは`md`とする。
- PCサイドバーは`md`以上で表示する。
- モバイルボトムナビは`md`未満で表示する。
- 横長表はモバイルでカードへ置換する。
- Calendarはスマートフォンで日表示を初期表示とし、画面幅内に収める。
- ダイアログはモバイルでは下端シート、PCでは中央モーダルにする。

## 13. アクセシビリティ

- リンクとボタンにキーボードフォーカスリングを表示する。
- アイコンだけのボタンには`aria-label`を付ける。
- ダイアログは`role=dialog`、`aria-modal=true`、見出し参照を持つ。
- 現在地には`aria-current`を付ける。
- 色に加えてラベル、枠線、文言で状態を区別する。
- 主要タップ領域はおおむね40px以上を確保する。

## 14. デザイン監査基準

各主要画面を次の順で評価する。

1. 3秒で画面目的が分かるか
2. 最重要情報から自然に視線が移るか
3. 次に押す操作が明確か
4. 文字、色、余白に十分な可読性があるか
5. 空・失敗・処理中の状態が理解できるか
6. スマートフォンで横移動なしに主要操作できるか

重大な問題を修正した後、同じ基準で最大2回再評価する。

## 15. 実装ルール

| ルール | OK | NG | 適用外 |
|---|---|---|---|
| 現在地を示す | active背景＋aria-current | 全リンクが同じ見た目 | 認証前画面 |
| 低信頼だけ強調 | 75%未満に警告 | 全項目を常時警告 | AI以外の手入力フォーム |
| モバイル表をカード化 | 応募・期限カード | 900px表の横スクロールだけ | Calendar本体 |
| 外部予定は詳細後に取込 | ダイアログで確認 | 1クリック即保存 | 内部予定の詳細遷移 |
