# ApplyFlow UI/UX設計書 v1.4

更新日: 2026-07-27

## 1. UXの目的

利用者が3秒以内に「次に対応すべき選考・期限・衝突」を把握し、メールやカレンダーから登録する手間を減らす。

最重要メッセージは「今やるべき選考対応が分かる」である。ブランド名ApplyFlow、青を中心とした配色、簡潔で実務的な口調を維持する。

## 2. 情報の優先順位

1. 今日・今週の確定面談
2. 返信待ち
3. 近づいている期限
4. 日程衝突
5. 進行中の応募
6. 外部メール・カレンダーからの登録

確定、候補、期限、Google予定、取込済み予定は色とラベルの両方で区別する。色だけに意味を依存させない。

## 3. 共通ナビゲーション

### PC

左サイドバーを使用する。

- ダッシュボード
- 応募先
- カレンダー
- 返信待ち
- 期限管理
- メール取込
- 設定

現在地は青背景と青文字で強調し、`aria-current=page`を付ける。

### スマートフォン

画面下部に固定した5項目のボトムナビゲーションを使用する。

- ホーム
- 応募
- 予定
- メール
- 設定

返信待ちと期限はダッシュボードのサマリーから到達できる。下部ナビとコンテンツが重ならないよう本文にsafe areaを確保する。

## 5. ダッシュボード

サマリーカード全体をクリック可能にし、対応する一覧へ遷移する。

- 今週の面談 → カレンダー
- 返信待ち → 返信待ち一覧
- 期限間近 → 期限管理
- 衝突 → カレンダー
- 進行中応募 → 応募先一覧

「今日・今週の予定」には確定面談、候補日時に加えて、Google Calendarから取り込んだ`ScheduleEvent`を表示する。応募先に紐付く予定は応募詳細へ、未紐付け予定はカレンダーへ遷移する。

カード内の数値を最も強く、名称、アイコンの順に見せる。下段には今日・今週、返信待ち、期限、衝突の詳細を配置する。

## 6. 応募先一覧

PCは比較しやすい表、スマートフォンは会社単位のカードを使用する。

カードには次を表示する。

- 会社名、ポジション
- 選考ステータス、応募種別、優先度
- 次の予定
- 最も近い期限

カード全体を詳細画面へのリンクにする。

## 7. カレンダー

### 表示

- PCの初期表示は週表示
- 月、週、日を切替可能
- 確定面談: 青
- 候補日時: 淡い青・破線
- 期限: 黄、承諾期限は赤
- 未取込Google予定: グレー
- 取込済み予定: 紫

上部に色と種別の凡例を表示する。

### イベント詳細

イベントを選択すると画面遷移せず詳細ダイアログを表示する。

表示内容:

- 種別、タイトル
- 日時
- 関連応募先
- 場所、説明
- Google側URL、面談URL

内部予定は応募詳細へ遷移できる。ダイアログは閉じるボタン、背景選択、Escapeで閉じられる。

### Google予定取込

未取込Google予定だけに取込フォームを表示する。応募先紐付けは任意とし、「紐付けない」を初期値にする。

処理中はボタンを無効化し、成功・失敗をダイアログ内に表示する。取り込み成功後はカレンダーを再読込し、取込済みの紫色表示へ切り替える。

カレンダー上部には「Google予定を一括取り込み」を表示する。実行前に利用者タイムゾーン基準の今月から翌月末までが対象であること、既存予定を更新すること、削除済みの同じ予定を再表示することを確認し、成功後は新規件数と更新件数を表示する。新規予定は応募先へ紐付けず、既存予定の紐付けは保持する。取得・保存が失敗した場合は画面内に失敗を表示する。

### 確定面談のGoogle Calendar登録

応募詳細の面談カードでは、`CONFIRMED`かつ開始・終了日時が正しい面談だけに「Google Calendarに登録」を表示する。利用者の明示操作後、処理中はボタンを無効化し、成功・登録済み・権限不足・API失敗を同じカード内に表示する。

成功時はGoogle Calendarで予定を開くリンクを表示する。追加scopeまたは再認証が必要な場合は設定画面への導線を表示し、そこでGoogle再ログインを実行できるようにする。登録対象はPrimary Calendar固定とし、自動登録やカレンダー選択UIは設けない。

## 8. Gmail取り込み

検索後、正常系はAI抽出から応募詳細へ直接進み、例外だけ抽出確認へ送る。

検索結果には件名、送信者、日時、スニペットを表示し、メールごとに「自動反映」を配置する。受付後は「自動反映中」と表示し、Background FunctionのJob結果を待って応募詳細または例外確認へ遷移する。通信例外でページ全体を落とさず、再読込して処理一覧を確認できる案内を表示する。

未連携・権限不足・期限切れは、原因説明と再ログインボタンを同じカードに表示する。

### Gmail監視

監視設定は「設定」のGmail連携カード内に置き、次を一つのまとまりとして表示する。

- 監視ON/OFF
- Gmail検索条件
- Cloudflare Workers AI上の`@cf/openai/gpt-oss-120b`へ本文を送信することと、高信頼時の自動反映への同意
- 最終実行、最終成功、最新エラー
- 自動反映、確認待ち、再試行、失敗の件数
- 「今すぐ実行」

初回有効化時より前のメールは処理しないこと、無料枠到達時は課金せず繰り越すことを有効化前に明示する。

Gmail取り込み画面の検索フォームより上に監視状況を短く表示し、job一覧には件名、送信者、受信日時、状態、対象応募、処理日時を表示する。メール本文やAI evidence全文は一覧へ表示しない。

| job状態 | 表示 |
|---|---|
| AUTO_APPLIED | 成功色、「自動反映済み」、応募先へのリンク |
| REVIEW_REQUIRED | 警告色、「確認が必要」、確認画面へのリンク |
| IGNORED | muted、「対象外」 |
| PENDING / PROCESSING / RETRY_WAIT | default、「処理待ち／処理中／再試行待ち」 |
| FAILED | danger、「処理失敗」、本文を含まない概要 |

## 9. AI抽出確認

画面上部に総合confidenceを表示する。75%以上は成功色、未満は警告色とする。

各抽出フィールドは項目別confidenceを参照し、75%未満の場合だけ次を表示する。

- 「要確認 xx%」バッジ
- AIが判断に使った短い根拠

高信頼項目まで警告で埋め尽くさず、利用者が修正すべき箇所に視線を集中させる。

登録前に会社、ポジション、選考、確定日時、候補日時、期限、URL、担当者を編集できる。候補日時は追加・削除できる。

## 10. 期限管理

PCは表、スマートフォンはカードを使用する。スマートフォンではタイトル、応募先、状態、日時、残り時間、完了操作を一画面幅に収める。

## 11. 状態表示

| 状態 | 表示方針 |
|---|---|
| 読込中 | 対象ボタンを無効化し動詞を進行形にする |
| 空状態 | 状態説明と、必要な場合は次の行動を表示 |
| 入力エラー | 対象フィールド直下に表示 |
| 外部APIエラー | 原因と再認証・設定・再試行導線を表示 |
| 成功 | 操作箇所の近くに短い結果を表示 |
| 破壊的操作 | destructive色と確認操作を使用 |

## 12. レスポンシブ

- 主要ブレークポイントは`md`とする。
- PCサイドバーは`md`以上で表示する。
- モバイルボトムナビは`md`未満で表示する。
- 横長表はモバイルでカードへ置換する。
- Calendarはスマートフォンで日表示を初期表示とし、画面幅内に収める。
- 画面回転時はCalendarを表示幅に合わせ、狭幅は日表示、広幅は週表示へ切り替える。
- ダイアログはモバイルでは下端シート、PCでは中央モーダルにする。
- iPhoneでは上下左右のsafe areaを固定ヘッダー、ボトムナビ、下端シート、認証画面の余白へ反映する。
- フォーム部品はモバイルで16px以上、主要タップ領域は44px以上とする。

## 12.1 iPhone Safari / PWA

- 対象はiPhone 14以降の、サポート中の最新iOS Safariとする。
- Web App Manifest、Apple Web App metadata、アプリアイコンを提供し、ホーム画面追加後は`standalone`で起動する。
- Service Workerはインストールと更新だけを担い、認証済みHTML、APIレスポンス、ユーザーデータをキャッシュしない。
- PWAはオンライン前提とし、Service Worker登録に失敗した場合も通常のSafariサイトとして機能を継続する。
- viewportは`viewport-fit=cover`を使うが、利用者のピンチズームは禁止しない。

## 13. アクセシビリティ

- リンクとボタンにキーボードフォーカスリングを表示する。
- アイコンだけのボタンには`aria-label`を付ける。
- ダイアログは`role=dialog`、`aria-modal=true`、見出し参照を持つ。
- 現在地には`aria-current`を付ける。
- 色に加えてラベル、枠線、文言で状態を区別する。
- 主要タップ領域は44px以上を確保する。

## 14. デザイン監査基準

各主要画面を次の順で評価する。

1. 3秒で画面目的が分かるか
2. 最重要情報から自然に視線が移るか
3. 次に押す操作が明確か
4. 文字、色、余白に十分な可読性があるか
5. 空・失敗・処理中の状態が理解できるか
6. スマートフォンで横移動なしに主要操作できるか

重大な問題を修正した後、同じ基準で最大2回再評価する。

## 15. 実装ルール

| ルール | OK | NG | 適用外 |
|---|---|---|---|
| 現在地を示す | active背景＋aria-current | 全リンクが同じ見た目 | 認証前画面 |
| 低信頼だけ強調 | 75%未満に警告 | 全項目を常時警告 | AI以外の手入力フォーム |
| モバイル表をカード化 | 応募・期限カード | 900px表の横スクロールだけ | Calendar本体 |
| 外部予定は詳細後に取込 | ダイアログで確認 | 1クリック即保存 | 内部予定の詳細遷移 |

## 16. 旧版からの変更

- Gmail/AI画面を将来構想から実装済み画面へ移行した。
- Gmail監視設定、実行状態、確認待ち導線を追加した。
- Calendarイベントクリックの仕様を直接遷移から詳細ダイアログへ変更した。
- Google予定取込フロー、項目別confidence、モバイルボトムナビを追加した。
- 英語中心のナビゲーションを日本語へ統一した。
