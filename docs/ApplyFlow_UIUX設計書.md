
# ApplyFlow UI/UX仕様書 v0.1

## 1. 目的

本書は、ApplyFlow の画面構成、画面遷移、主要UIコンポーネント、ユーザー操作フロー、表示ルールを定義する。

ApplyFlow は、就活・転職・インターン・業務委託案件応募における、応募先・選考フェーズ・候補日時・返信待ち・承諾期限・日程衝突を管理する選考CRMである。

UI/UX設計では以下を重視する。

- 確定予定と未確定候補日を区別して見せる
- 返信待ち・期限・衝突を優先的に見せる
- 応募先ごとの選考状況を時系列で把握できる
- 入力項目を増やしすぎず、MVPとして使える範囲に絞る
- スプレッドシートより速く、Google Calendarより選考管理に強い体験を作る

---

## 2. UX方針

### 2.1 ユーザーが最初に知りたい情報

ユーザーがログイン直後に知りたいのは、全応募先の一覧ではなく、今対応すべきこと。

優先表示する情報は以下。

1. 今日・今週の面談
2. 返信待ちの面談
3. 期限が近いもの
4. 衝突している候補日時
5. 選考が止まっている応募先

### 2.2 確定予定と候補日時を明確に区別する

このアプリの価値は、未確定の候補日時を扱える点にある。

そのため、UI上では以下を明確に分ける。

- 確定面談
- 提示中候補日
- 返信期限
- 承諾期限
- 衝突警告

候補日時は確定予定と同じ見た目にしない。

### 2.3 衝突はブロックではなく警告

候補日時は未確定であるため、衝突していても登録を禁止しない。

ただし、以下のように警告する。

- 他社に提示中の候補日時と重複しています
- 確定面談と重複しています
- 承諾期限前に他社選考が完了しない可能性があります

### 2.4 詳細入力より素早い登録を優先する

初回登録時にすべての情報を入力させない。

最小入力：

- 会社名
- ポジション
- 選考フェーズ
- 候補日時

詳細情報は後から追記できる設計にする。

## 4. 画面遷移

### 4.1 基本遷移

```txt
/login
  -> /dashboard
      -> /applications
          -> /applications/[id]
              -> /applications/[id]/edit
      -> /calendar
      -> /waiting
      -> /deadlines
      -> /settings
```

### 4.2 応募登録フロー

```txt
/dashboard
  -> 応募先を追加
  -> /applications/new
  -> 作成
  -> /applications/[id]
```

### 4.3 候補日時登録フロー

```txt
/applications/[id]
  -> 選考フェーズを追加
  -> 面談を追加
  -> 候補日時を追加
  -> 衝突チェック
  -> 保存
  -> 応募先詳細に反映
  -> カレンダーに表示
```

### 4.4 候補日時確定フロー

```txt
/applications/[id]
  -> 候補日時を選択
  -> 確定する
  -> 確認ダイアログ
  -> 選択候補を confirmed
  -> Interview を confirmed
  -> 他候補を rejected / cancelled
  -> ActivityLog 作成
```

### 18.1 応募先作成

- 会社名：必須、1〜100文字

- 期限タイトル：必須

- 期限日時：必須
- 過去日時は警告するが登録可

## 24. 設計上の重要判断

### 24.1 ダッシュボードを最優先画面にする

ユーザーは「全応募先」ではなく「今何をすべきか」を知りたい。

そのため、ログイン後は応募先一覧ではなくダッシュボードへ遷移する。

### 24.2 応募先詳細を中核画面にする

選考状況は応募単位で進むため、応募先詳細にタイムライン・面談・候補日時・期限・活動ログを集約する。

### 24.3 候補日時はカレンダーと詳細の両方に出す

カレンダーだけでは文脈が不足する。

応募先詳細だけでは時間軸が見えない。

そのため、候補日時は両方に表示する。

### 24.4 Gmail/AI関連画面はv1.0まで作らない

初期実装でGmail取り込み画面まで作ると、MVPが肥大化する。

v0.1では手入力体験を完成させる。

---

## 25. まとめ

ApplyFlow のUI/UXは、通常の予定管理ではなく、選考プロセス管理に最適化する。

中核画面は以下の3つである。

- ダッシュボード
- 応募先詳細
- カレンダー

この3画面で、返信待ち・候補日時・承諾期限・衝突を確認できれば、MVPとして成立する。

v0.1では手入力中心の堅実なUIを作り、v0.2でGoogle Calendar、v1.0でGmail/AI連携を追加する。
